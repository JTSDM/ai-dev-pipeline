# AI 开发流水线（ai-dev-pipeline）总纲

> **操作细节以 SKILL.md 为准**：本文件只讲"为什么、何时用、原则与陷阱"，不复制具体步骤、模板与落盘路径。具体操作见 SKILL.md（本包内）。
>
> **原则性变更需同步至本文档**：仅当流程原则、裁剪阈值、生命周期规则、方法论来源发生变化时更新本文档（其余变更只改 SKILL.md，不回写本文档）；操作步骤/模板/DoD 变更只改 SKILL.md。
## 1. 方法论来源

- **Matt Pocock**（AI Engineer Summit 演讲"Software Fundamentals Matter More Than Ever"）：AI 写代码越写越烂，不是 AI 的问题，是你丢了软件基础。
- **5 个技巧**（层层递进，非并列）：
  1. Grill Me（拷问）—— 写代码前让 AI 反问你，达成共同设计概念（Brooks《设计的设计》）
  2. 统一语言（Ubiquitous Language）—— 扫代码库生成术语表，AI 不再啰嗦、不再猜（Evans《DDD》）
  3. TDD 强制小步迭代 —— 防 AI"跑得比大灯快"（《程序员修炼之道》）
  4. Deep Module > Shallow Module —— 防 AI 造碎片海（Ousterhout《软件设计的哲学》）
  5. 设计接口、委托实现 —— 人在战略层，AI 在战术层
- **社区流水线**（mattpocock/skills v1.1）：grill-with-docs → to-spec → to-tickets → implement → code-review
- **瀑布流 2.0 洞见**：长上下文模型 + 高推理模式让"回退重来"几乎免费，敢重新回到"先规划后执行"。研究和规划是最高杠杆的动作，写代码反而不是。

## 2. 核心概念

| 概念 | 一句话 |
|------|--------|
| 共同设计概念 | 编码前与 AI 达成共享理解，否则 AI 会用貌似合理的猜测填坑 |
| 统一语言 | 项目术语表（CONTEXT.md），所有 AI 对话引用，减少 token 浪费与命名漂移 |
| TDD 控制回路 | 当代码生成器是"产出貌似合理输出的机器"时，失败的测试是最便宜的 oracle |
| Deep Module | 大量功能藏在简洁接口后面；AI 天然爱造浅模块碎片海，要持续重构封装 |
| 接口设计/委托实现 | 人设计模块边界和接口，AI 实现内部细节，人在接口处写测试验证 |
| 交接物 = 文件 | 不是聊天记录；文件能扛过换模型、清上下文、下周再干 |

**核心洞见**：流水线里没有一步叫"写代码"。规划阶段（grill/spec/tickets）的质量决定 AI 产出的质量。

## 3. 5 步流水线（概念层）

产出物只写概念，不写具体路径/模板（路径见 SKILL.md）。

| 阶段 | 输入 | 产出物 | 要点 |
|------|------|--------|------|
| Grill（拷问） | 原始想法/需求 | 决策记录 + 项目术语表 | 穷举追问直到消除关键歧义；未决问题显式标记 |
| Spec（规格） | 决策记录 | 规格说明（统一语言+模块边界+接口签名） | 只到接口层，不写实现；验收标准可映射测试 |
| Tickets（拆票） | 规格说明 | 任务清单（每项含验收标准） | 竖切不横切；标 HITL/AFK |
| Implement（实现） | 任务清单 | 通过的测试 + 实现代码 | 测试先行；一次一小步 |
| Review（审查） | 实现产物 + 规格/任务 | 审计结论 | 对照规格 + 仓库标准双轴审计 |

**交接物模板**：DECISIONS / SPEC / TICKETS / CONTEXT 的填写模板见 SKILL.md 的 `references/templates/`（本文件不复制模板内容，仅指引位置）。

## 4. 分级裁剪矩阵

| 档位 | 适用 | 流程 |
|------|------|------|
| **L 大任务** | 新项目/新模块/架构级决策 | 完整 Grill → Spec → Tickets → Implement → Review |
| **M 中任务** | 单功能/跨文件改动 | 10 问自检（可默认则跳过）→ Spec → Tickets → Implement → Review |
| **S 小改动** | 修 bug/改文案 | 一行最小任务描述（含验收标准+测试）→ Implement → Review |

原则：**按"出错成本"选档**。改个表单校验也跑全流程，你两周后就不会再用它了。S 档也必须留下文件可追踪，只是不做规划。

## 5. 常见陷阱与回退策略

- **Spec-to-Code 陷阱**：出 bug 就改 spec 重新生成 → 软件熵，每循环一次代码更烂。正确做法是"人盯接口，测试约束实现"。
- **流程过重被架空**：分级裁剪是防呆关键，S 档必须轻。
- **交接物只存在聊天记录里**：一旦换窗口/换模型就丢失。一切落盘。
- **文档与 skill 双写漂移**：SKILL.md 是唯一操作事实源，本文档只写原则；原则变化才更新本文档。
- **回退策略**：发现规格级错误回退到 Spec；实现级错误回退到 Implement；M 档歧义触发 mini-Grill（不回独立 Grill 阶段）。

## 6. 生命周期规则

- **过程文件**（任务清单等）：任务完成后归档或删除，只留验收记录。
- **长期资产**（决策记录、规格说明、项目术语表）：纳入版本控制，供后续 AI 对话引用。
- **术语表**：项目启动时从通用模板生成项目专属版本，随项目演进维护。
- **记忆系统**：交接物在文件；记忆只记「流程跳变/回退原因」，不重复交接物内容。
